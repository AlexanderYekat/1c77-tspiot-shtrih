# ТЗ: статус проверки марки на форме чека

## Цель

Кассир видит статус проверки КМ (проверяется / OK / ошибка) по данным из сервиса ККТ, без блокировки UI.

## Уже есть (болванки)

| Место | Что |
|--------|-----|
| Форма чека | `ПолучитьСтатусПроверкиМарки()` — читает статус для UI; уже повешена на форму, вызывается автоматически; `Маркировка` = марка текущей строки |
| Форма чека | после скана/ввода КМ: async `check-marks` + `ОбработкаОжидания("глПроверитьСтатусПроверокМаркок", 5)` |
| Глобальный модуль | `глРезультатыПроверокМарок`, `глПроверитьСтатусПроверокМаркок()` (тест-счётчик) |
| Сервис | `POST /kkt/check-marks` → `taskId`; `GET /kkt/check-marks/status?taskId=…` → `pending` / `completed` / `error` |

## Что сделать

### 1. Хранилище результатов (глобальный модуль)

- `глРезультатыПроверокМарок` — `СписокЗначений` (или ТЗ), ключ = сырая марка (`СокрЛП`).
- Обязательно `Экспорт` (сейчас без него — с формы не видно).
- В значении минимум: `taskId`, `статус` (`ожидание` / `ok` / `ошибка` / `проверяется`), короткое `описание`, при необходимости `allAccepted`.
- Инициализация при старте сеанса (пустой список).

### 2. При старте проверки (форма чека)

В `ВыполнитьПроверкуМарокАсинхронно` после получения `taskId`:

- записать в `глРезультатыПроверокМарок` пару «марка → taskId + статус=`проверяется`»;
- вернуть `taskId` как сейчас.

`ОбработкаОжидания(..., 5)` оставить.

### 3. Опрос статусов — `глПроверитьСтатусПроверокМаркок`

- Пройти незавершённые записи (`проверяется` / `ожидание`).
- Для каждой: быстрый `GET /kkt/check-marks/status?taskId=…` (тот же WinHttp / хост-порт, что для check-marks; короткий таймаут).
- По ответу обновить запись в `глРезультатыПроверокМарок`:
  - `pending` → оставить «проверяется»;
  - `completed` → `ok` или `ошибка` по `allAccepted` / `result` / `marks`;
  - `error` / сеть → `ошибка` + описание.
- Если незавершённых нет — `ОбработкаОжидания("")` (остановить таймер).
- Не блокировать кассу: один проход по списку, без длинных циклов ожидания внутри процедуры.

### 4. UI — `ПолучитьСтатусПроверкиМарки`

- По текущей `Маркировка` (марка текущей строки табличной части) взять запись из `глРезультатыПроверокМарок`.
- Вернуть короткую строку для формы, например: `проверяется` / `OK` / `ошибка: …`.
- Нет записи / нет сервиса → пустая строка.
- Убрать зависимость от `глТестСч`.
- Привязка к UI уже сделана: функция вызывается платформой автоматически.

### 5. Очистка

При очистке буфера марок / закрытии чека — чистить соответствующие записи в `глРезультатыПроверокМарок` и при необходимости останавливать ожидание.

## Поток

```
скан КМ → POST check-marks (async) → taskId в глРезультаты…
                ↓
    каждые 5 с: глПроверитьСтатусПроверокМаркок → GET status → обновить глРезультаты…
                ↓
    ПолучитьСтатусПроверкиМарки() (автовызов) → строка по Маркировке текущей строки
```

## Не в scope

- Менять Delphi/proxy API.
- Блокировать печать чека по статусу UI (печать по-прежнему опирается на кэш Delphi).
- Poll чаще 5 с, пока не попросите иначе.

## Критерий готовности

1. После ввода КМ в UI появляется «проверяется».
2. После завершения задания на сервисе — «OK» или «ошибка» без перезапуска формы.
3. Несколько марок в чеке — у каждой свой статус.
4. Когда все проверки завершены — таймер `ОбработкаОжидания` останавливается.
